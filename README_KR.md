# DataCo Supply Chain Analysis

**Python, Prophet, Power BI를 활용한 공급망 배송 성과 분석 및 단기 수요예측 프로젝트**

## 프로젝트 개요

본 프로젝트는 DataCo Supply Chain 데이터를 활용하여 물류 운영 관점에서 다음 두 가지 핵심 문제를 분석했습니다.

1. **배송 지연은 어떤 운영 조건과 가장 강하게 연관되어 있는가?**
2. **단기 일별 수요를 예측하여 물류 운영계획에 활용할 수 있는가?**

데이터 검증, 탐색적 데이터 분석, 시계열 수요예측, Power BI 대시보드 구축까지 하나의 분석 프로세스로 진행했습니다.

## 주요 분석 질문

다음 질문을 중심으로 분석을 진행했습니다.

- 어떤 배송방식에서 배송지연률이 높은가?
- 지역, 상품 카테고리, 월별로 배송지연률에 의미 있는 차이가 존재하는가?
- 배송방식별 예정 배송일과 실제 배송일에는 어느 정도 차이가 발생하는가?
- 일별 상품 처리량을 이용하여 단기 수요를 예측할 수 있는가?
- Prophet 모델은 단순 7일 이동평균 기준 모델보다 높은 예측 성능을 보이는가?

## 데이터 전처리

실제 물류 운영 성과를 분석하기 위해 취소된 배송은 분석 대상에서 제외했습니다.

`Delivery Status != 'Shipping canceled'`

배송지연 분석의 주요 지표로는 다음 변수를 사용했습니다.

`Late_delivery_risk`

- `1` = 배송지연
- `0` = 정상 배송

수요예측에서는 취소 주문을 제외한 일별

`Order Item Quantity`

합계를 예측 대상으로 사용했습니다.

## 데이터 품질 검증

수요예측을 진행하기 전에 데이터 구조를 검증하는 과정에서 중요한 구조 변화가 발견되었습니다.

**2017-10-03 이전에는 하나의 `Order Id`가 여러 행에 걸쳐 나타날 수 있었지만, 2017-10-03 이후부터는 관측된 주문 하나가 정확히 한 행으로 표현되는 구조로 변경되었습니다.**

이러한 구조 변화는 행 단위 상품수량에 직접적인 영향을 미치기 때문에, 이후 데이터에서 나타나는 급격한 물량 감소를 실제 수요 감소로 해석할 수 없습니다.

따라서 수요예측에는 구조적으로 비교 가능한 다음 기간만 사용했습니다.

**2015-01-01 ~ 2017-10-02**

이를 통해 데이터 표현 방식의 변화를 실제 수요 감소로 잘못 해석하는 문제를 방지했습니다.

## 배송 성과 분석

취소 배송을 제외한 전체 배송지연률은 약:

**57.29%**

였습니다.

### 배송방식별 배송지연률

| 배송방식 | 배송지연률 |
|---|---:|
| First Class | 100.0% |
| Second Class | 79.8% |
| Same Day | 47.9% |
| Standard Class | 39.8% |

분석한 변수 중 **Shipping Mode에서 가장 큰 배송지연률 차이**가 나타났습니다.

### 예정 배송일 vs 실제 배송일

| 배송방식 | 예정 배송일 | 실제 배송일 |
|---|---:|---:|
| First Class | 1.0일 | 2.0일 |
| Second Class | 2.0일 | 약 4.0일 |
| Same Day | 0.0일 | 약 0.48일 |
| Standard Class | 4.0일 | 약 4.0일 |

예정 배송일과 실제 배송일의 차이가 큰 배송방식에서 높은 배송지연률이 함께 관찰되었습니다.

다만 본 분석은 관측 데이터에 기반한 분석이므로, **배송방식이 배송지연의 직접적인 원인이라고 단정하지 않고 연관관계로 해석했습니다.**

### 지역, 상품군 및 시간 분석

다음 항목별로도 배송지연률을 비교했습니다.

- Order Region
- Category Name
- 월별 배송지연률

하지만 이 변수들의 차이는 Shipping Mode에서 나타난 차이에 비해 상대적으로 작았습니다.

따라서 DataCo 데이터에서는 지역이나 상품군, 월별 차이보다 **배송 서비스 구조와 배송지연 성과 사이의 연관성이 더 뚜렷하게 나타났습니다.**

## 수요예측

수요예측의 목표 변수는:

**취소 주문을 제외한 일별 `Order Item Quantity` 합계**

입니다.

### Train / Test 구간

- Train: **2017-06-30까지**
- Test: **2017-07-01 ~ 2017-10-02**
- Test 기간: **94일**

## 기준 모델: 7일 이동평균

우선 복잡한 모델과 비교하기 위한 기준 모델로 7일 이동평균을 사용했습니다.

각 날짜의 예측값은 **직전 7일의 실제 물량 평균**을 사용하여 계산했습니다.

### 7일 이동평균 성능

- MAE: **29.93**
- RMSE: **39.46**

## Prophet 모델

Prophet은 기준 모델과 공정하게 비교하기 위해 **Walk-Forward Validation** 방식으로 평가했습니다.

평가 과정은 다음과 같습니다.

1. 이전 날짜까지의 데이터로 모델 학습
2. 다음 날짜의 수요 예측
3. 해당 날짜의 실제값을 데이터에 추가
4. 업데이트된 데이터로 모델 재학습
5. 다음 날짜를 다시 예측

이 과정을 전체 94일의 테스트 기간에 반복했습니다.

### Prophet 성능

- MAE: **28.64**
- RMSE: **38.26**

Prophet이 7일 이동평균 기준 모델보다 약간 낮은 예측오차를 기록했습니다.

다만 성능 차이가 크지는 않았기 때문에, Prophet이 기준 모델을 압도적으로 개선했다고 해석하지 않았습니다.

## 시계열 패턴 분석

수요 데이터의 시계열 특성을 추가로 확인한 결과:

- 요일별 수요 차이는 크지 않았음
- 2017년에 수요 수준이 감소하는 추세가 관찰됨
- 월별 차이는 존재하지만 연도별로 동일하게 반복되는 안정적인 계절성은 아니었음

따라서 Prophet의 성능 개선에는 강한 요일 효과보다는 **시간에 따라 변하는 수요 수준과 여러 시계열 패턴을 동시에 반영하는 능력**이 일부 기여했을 가능성이 있습니다.

## 향후 7일 수요예측

구조 변화 이전의 모든 유효 데이터를 사용하여 최종 Prophet 모델을 학습했습니다.

예측 결과는 다음과 같습니다.

| 날짜 | 예상 물량 |
|---|---:|
| 2017-10-03 | 331.34 |
| 2017-10-04 | 329.83 |
| 2017-10-05 | 332.52 |
| 2017-10-06 | 334.98 |
| 2017-10-07 | 330.83 |
| 2017-10-08 | 332.59 |
| 2017-10-09 | 326.38 |

단기 수요는 대략:

**하루 약 330 units**

수준으로 유지될 것으로 예측되었습니다.

다만 2017-10-03부터 실제 데이터 구조가 변경되기 때문에, 이 예측 결과는 이후 실제값과 직접 비교하여 모델 정확도를 검증하기 위한 결과가 아니라 **물류 운영계획을 위한 단기 시나리오 예측값**으로 해석했습니다.

6. **2017-10-03 데이터 구조 변화 발견을 통해 데이터 품질 검증이 분석 결과 해석에 중요하다는 점을 확인했습니다.**
